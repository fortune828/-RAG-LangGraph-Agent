# 知识语义与回答可靠性优化 · 2026-10-10

本轮取得的是**局部、可解释的改进**：减少无关爻注进入上下文，修正爻名数据，恢复可唯一定位的繁简引文，让截断回答有一次修复机会，并修正一次真实的归属校验误拒。**独立四题对照没有显示整体语义质量提升；连续追问仍有事实漂移和牵强类比。** 不以工程通过或检索命中替代产品验收。

## 最终方案

保留 Python / FastAPI / LangGraph、固定知识发布、现有普通段落与 claim 引用协议。单一 `deepseek-flash`：主调用 Thinking low / 8192，一次修复 disabled / 8192。起卦、历史存储、权限和前端不改；提示词仍是 **v16，未增加写作规则**。没有新模型、向量库、润色 Agent 或额外常规生成调用。

| 环节 | 实际采用 | 依据与边界 |
|---|---|---|
| 固定取证 | 原典照常；爻注限实际动爻或用户明确所问爻位 | 旧词面排序会因“不能”选入静卦的不同爻注，制造无关分析机会；不据此删除全部注解 |
| 明确取证 | 完整匹配的本卦纯文献请求由程序规划 get_passages | 同样经过权限、参数、去重、三次尝试及证据预算；混合现实问题、模糊出处保留模型路由 |
| 模型上下文 | 提供程序计算的“初六、九二”等爻名，爻性另列 | 旧“爻名”实际装的是“少阴、少阳”；修正输入不代表能验证正文所有传统断言 |
| 引文 | 唯一原文片段定位后返回原文字符 | 只用现有繁简映射及标点空白归一；不模糊匹配、不补词、不改 claim；多处匹配仍拒绝 |
| 失败恢复 | 主生成 length 进入原有一次非思考修复 | 空正文、残缺 JSON、可解析但截断的 JSON 都不直接放行；再次失败结束，HTTP/路由错误不增加重试 |
| 归属校验 | 区分“说”这一观点动词与“说法”这一名词 | 保留真正的作者观点断言及邻句检查；不是用免责声明豁免整段 |

版本分开保存：基线提交 `f277be7f880c368cd549e0f956555be982975a34` 是 graph v13 / prompt v16；四题隔离确认冻结在 **graph v14**；随后独立代码复核使精确快捷取证收紧为纯文献语法，发布与连续对话、压力题记录为 **v15**。最后归属词性修正另记 **v16**，只做原候选离线重校验和工程回归，不把 v14/v15 的真实运行重标成 v16。知识库始终为 `knowledge-v3-20260926-r1`。

## 最有价值的发现

**1. 文献是否相关，比文献数量更关键。** 一个静卦责任更正问题仅因含“不能”，旧准备选入恒卦六五、上六、初六注；模型随后扩展了与当前更正无关的解释。固定同一问题、历史、模型与生成消息形式，只改变这部分证据，旧组 7,760 tokens / 30.79 秒，新组 4,227 / 16.72 秒。独立 AI 的用户事实、传统含义、类比贴切、交流帮助四维为 **1/1/1/2 → 2/2/2/2**。这是单个已知开发案例，不能外推总体改善。[完整双组回答](../../../evaluation/reports/semantic-20261010/static/answers.md)

程序准备收紧也没有解决所有过检索：真实连续对话中 Router 仍主动取得恒卦额外爻注，随后将再次道歉等同于“振恒”。因此“初始证据更相关”与“整个 Agent 能始终选对材料”必须分开。

**2. 注解可以修正文义，但没有自动修正现代应用。** 两个生活问题分别围绕坎六四答谢朋友、蒙上九带新人。memory 允许模型自有知识、引用为 N/A；classic 只给原典；full 加入现有对应注解。三组同模型、同输入，各单元一次生成，不修复：

| 知识输入 | 机械完成 | 总 tokens | 中位延迟 |
|---|---:|---:|---:|
| memory | 2/2 | 5,113 | 12.66 秒 |
| classic | 2/2 | 12,669 | 26.28 秒 |
| full | 0/2 | 18,552 | 34.03 秒 |

“纳约”的 memory/classic 回答出现“约定、坦诚”等缺少本次文献支持的解释；王弼“约，俭约也”与朱熹“薄礼益以诚心”使 full 的词义更有依据。这是 **AI 对固定文本的核对，非专家 Gold，也不排除未收录的其他解释传统**。但 full 一题六条引用超限，另一题 length；两份失败各复放一次非思考修复后可交付，增加 6,960 tokens。原 0/2 不改写成 2/2，修复复放不增加独立样本数。

修复后的答案仍说“只要真诚、及时、量力，就不会失礼”；带新人题还编出“已经讲过两次”。可见原义更清楚与现实推断更克制不是同一个收益。两份修复答案的 AI 传统含义均为 2，现代类比均为 1。[三组完整回答](../../../evaluation/reports/semantic-20261010/rag/answers.md)、[原失败的一次修复](../../../evaluation/reports/semantic-20261010/rag-recovery/answers.md)、[语义参考](../../../evaluation/reports/semantic-20261010/fixtures/rag-development.json)

**3. Agent 有定位模糊出处的局部能力，尚未形成整体优势。** 已有四题开发对照中，有效 C 规则 Workflow 4/4 机械完成，4 次模型请求、22,378 tokens；旧 Agent 2/4、9 次、40,244 tokens。尝试“回答或工具合一”的候选虽然 4/4，却在责任更正题取来 19 条材料，产生更多无依据判断，故删除该生产候选，源码和负面结果留档。逐题初始证据 ID 相同，但旧/新图还改变了爻名数据和恢复机制，因此这是候选组合筛选，不能把全部差异归给路由策略。[C / 旧 Agent / 被拒候选](../../../evaluation/reports/semantic-20261010/hybrid/answers.md)

另外选了一条现代转述与目标古文无二元词重合的压力题。**题目按 C 词面失败挑选，不是公平总体 benchmark 或留出集。** C 确实搜索但漏掉目标；D 两次搜索也未直接命中，随后自主提出坎六四的定位假设，调用精确工具取得了朱熹原文。这个“提出出处假设→向真实语料核实”的行为有价值；模型记忆只用于找材料，不能当证据。

| 压力题 | 取得目标 | 真实最终交付 | 模型请求 / 工具尝试 | tokens |
|---|---|---|---:|---:|
| C/W1 | 否 | 不足回答，未完成出处确认 | 1 / 1 | 6,049 |
| D/W2（v15） | 是 | 被归属校验误拒，未完成交付 | 4 / 3 | 15,955 |

D 的拒绝来自“王弼等说法”被当成“王弼说”的断言，最后一次修复仍被拒。修正该词性边界后，按原证据、原 targets 和 requireCitations 完整离线重校验，两份候选均通过；**不重写这次端到端失败**。对上一轮 86 份、本轮 53 份可解析候选做词性差分，只有这两份消除同一误报，其余不变。[局部差分](../../../evaluation/reports/semantic-20261010/attribution-diagnostic/report.md)、[完整契约重校验](../../../evaluation/reports/semantic-20261010/attribution-diagnostic/full-contract.json)。候选本身也把九二注扩大为坎卦整体处境，并夹带与出处任务无关的起卦说明；找到出处不能算整答优质。[实际交付](../../../evaluation/reports/semantic-20261010/stress/answers.md)、[候选及逐次调用](../../../evaluation/reports/semantic-20261010/stress/paraphrase-stress-2-D.jsonl)、[完整选题过程](../../../evaluation/reports/semantic-20261010/fixtures/stress-design.md)

## 独立确认与真实连续对话

四个输入由未看候选结果的子 agent 编写，主优化者在读取题干前冻结 v14 候选和配置。覆盖睡眠与追剧、合唱团角色取舍、室友事实更正及朱熹豫六二文义；同模型、同卦象、同历史，配对交错，各一次运行，不择优补跑：

| 冻结四题 | 机械完成 | 模型请求 | 总 tokens | 中位延迟 | 估算 USD |
|---|---:|---:|---:|---:|---:|
| v13 基线 | 4/4 | 7 | 33,266 | 19.51 秒 | 0.012534 |
| v14 候选 | 4/4 | 7 | 30,346 | 18.32 秒 | 0.010683 |

AI 四维均分两组完全相同：**事实承接 2.00、传统含义 2.00、现代类比 1.00、交流帮助 1.75**。前三项中类比只计三条生活题，文献题为 N/A；其他项每组四条。样本少且只有一次采样，Token/延迟变化不能宣称显著收益或稳定性提升。两组都仍有静卦外推现实节奏、由意象保证处事后果等问题。[完整前后对照](../../../evaluation/reports/semantic-20261010/final/answers.md)、[盲评理由](../../../evaluation/reports/semantic-20261010/blind/final/report.md)、[运行前冻结](../../../evaluation/reports/semantic-20261010/decision.json)

v15 三轮连续对话使用**实际上一轮回答**：先谈搭档交稿迟，再更正为自己数据迟，最后说明对方已接受并问是否还要道歉。3/3 机械完成，7 次请求、44,308 tokens。模型能承认新事实，但第三轮将原本用户负责的合并改成搭档负责，又把反复道歉直接等同“振恒”。独立 AI 指出原义与现实类比、事实漂移需分开扣分。这是一个会话组，不是三个独立用户。[完整连续对话](../../../evaluation/reports/semantic-20261010/continuous/answers.md)、[逐轮评价](../../../evaluation/reports/semantic-20261010/blind/continuous/report.md)

## 稳定性、费用与没有采用的方案

- 重新组织为真实 User/Assistant 消息、按卦爻分组证据、只给本卦核心原典：16 个开发单元没有一致语义优势，未改生产历史或证据格式。core 还出现模型按记忆解释未提供的变卦。[全部上下文消融](../../../evaluation/reports/semantic-20261010/context/answers.md)

## 仍需解决

1. **从卦意跳到现实结论仍不可靠。** 更多原文能解释字义，却不能阻止“守正就无咎”被套成沟通无风险。优先对已保存的原义、比喻关系、事实分别做少量真人逐句确认，不能靠再添风格禁令证明解决。
2. **真实连续对话有过检索和角色事实漂移。** 第三轮错误合并职责是明确失败；“不再道歉”虽有实际建议，展开却没有增进判断。尚未证明删除历史或禁止追问取证更好，因此保留机制与负面结果。
3. **未知出处和换题识别仍有程序/模型边界。** 旧目标解析会把“哪一爻”读成“一爻”，多卦多爻还会产生交叉目标；本轮保守快捷取证不会绕过这些歧义，未宣称已修好整个解析器。混合新题真实 Router 仍漏判。
4. **没有线上可靠性、正式 Recall 或整体质量提升结论。** 四题确认、按规则失败选出的压力题都不替代 40+40、领域专家与实际用户。最终 v16 的词性修正只接受离线和工程验证，没有新一轮未见端到端样本。

本轮停止追加实验与写作规则，保存本地 Git，不推送。最终自然交流质量仍由用户阅读完整回答决定是否验收。
