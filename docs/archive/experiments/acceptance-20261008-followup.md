## 已落实的修改

| 修改 | 可核对的行为与证据 |
|---|---|
| 开发场景背景隔离 | 独立出处、医疗、投资、危机场景使用自己的初始问题；生活链仍共享原始问题。`test_development_fixtures.py` 覆盖独立场景和链内继承，不删除真实历史来制造通过。 |
| 最终生成上下文裁剪 | 路由保留执行上下文；生成只收到当前问题、有限用户事实、相关原文及自然语言限制。没有原始工具日志、旧助手全文或英文路由字段；`test_generation_context.py` 检查实际模型输入。风险输入不带卦象。 |
| 资料缺失判断与证据过滤 | 按发布集精确元数据区分已取得、可取得、未收录；未知书名独立保留，关键词零结果不证明全库缺失。作者和作品条件同时匹配，最终生成及校验使用筛选后的证据。已确认缺失不再强迫空查；未知名称仍保留路由机会。 |
| 段落类型契约 | 新输出 kind 必填：interpretation 必须引用；reflection 不得引用。仍校验原文、ID、目标爻位和显式归属。违规沿用一次 repair，耗尽走已有技术失败机制。旧答案无 kind 仍可读，不调用模型回填。 |
| 回答边界 | 不再统一要求固定段数；出处问答限制额外生活建议。明确重起卦由 prepare 直接到 finish，给出操作提示，模型与工具调用为零，原卦不变。 |

## 语义复核与尚未关闭的事项

1. **传统解释与现实建议分段改善。** 换工作首次回答及纠正积蓄案例已采用有引用的 interpretation 与无引用的 reflection；未靠放开伪造引用校验解决问题。但 kind 只验证声明和引用形态，不能证明文本确实符合声明；旧家庭沟通、注入案例尚未逐一重跑。T01 保留待完整语义验收。
2. **生活追问仍有重复。** 补充约束、纠正事实、切换家务沟通都正确使用当前问题，但仍重复乾卦解释，尚未达到理想的简短对话。没有为此新增摘要模型或长期记忆系统。
3. **缺失范围措辞仍不够准确。** source-missing 没有冒充焦循或补别家引文，但将“未收录作者注解”和“未知书名”同时展开，出现“没有对应爻辞文本”的模糊说法。实际缺失的是所问注解，不能将其理解为资料库没有乾卦爻辞。机械缺失判断已修正，表达仍需收敛。
4. **风险回答仍有多余限制说明。** 投资场景明确否认收益保证并提供现实支持，但先解释“没有可引用原文”并无必要；能否保证收益与有无原文无关。测试背景串入已修复，不把剩余生成问题归咎于 fixture。
5. **历史窗口仍有解释过多。** 不再泄漏 recentHistory 等字段，不猜测已不可见的 17 个月；但仍枚举第 1～6 项历史，宜直接请用户补充。T05 不因英文字段消失就宣布语义完全通过。

T02、T03、T04、T06、T07、T08 保留已有验收状态；T01、T05、T13 暂不整体关闭。T09～T12 的 40+40、B/C/D、真人盲评，以及 T14～T15 的完整交付工作没有在本轮冒充完成。相关当前说明已同步 README、SPEC、architect、tasklist 与 evaluation；不改写历史报告数据。
