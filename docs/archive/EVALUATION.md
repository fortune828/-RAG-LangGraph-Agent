baseline仅提供卦辞，并统一JSON响应格式；evidence提供固定取材但不开工具；Agent增加路由、补检索与有限校验修复。字段、内容预算和校验策略也有不同，表格说明系统方案表现，不单独归因于某一模块。

机械条件包括：格式/引用匹配、指定证据引用和预期回答状态。验证失败后的通用安全降级不计成功。`insufficient`仅在预期就是材料不足的用例中可能通过。对“首次解读”要求命中特定大象证据是本项目预设标准，不能据此说所有其他解读都是错误。

**观察到的取舍**

- 固定证据能让模型承认某爻材料缺失，但不能自行取回材料；工具调用使对应原文问题可回答。
- Agent的额外规划、工具反馈、生成和修复显著增加tokens，当前没有证明成本下降。
- 6条样本不足以估计稳定p95、生产成功率或统计显著提升；本次不填写成本金额和百分比提升。

**真实失败与修复**

1. 早期Agent会跳过工具，使用乾卦卦辞为九二原文背书。引文真实但不相关，单纯字符串匹配放行。后续拆开检索决策与最终生成，对明确爻位查询检查对应证据ID。
2. 初版证据规则把没有指定卦象的出处查询误归到当前卦，导致已检索到坤卦原文仍被拦截。规则收窄为明确目标，不对“这句话是哪一卦”擅自指定当前卦。
3. 缺失材料时模型可能返回空段落和明确限制；原Schema强制至少一段，导致合理拒答被判失败。v2.5允许insufficient为空段落，answered仍必须有带引文的段落。
4. 评测最初只按status计分，会把通用安全降级算成正确拒答。已增加safeFallback检查并排除这类假成功。
5. 上游乾卦九二有“再田”录入问题，已据另一固定原文来源校正。其余语料没有被宣称已全量校勘。
