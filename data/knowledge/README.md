- 全部新增注解是 **机器规则提取、零条人工审定**。校验来源片段可复原，不能证明底本无误或注释学归属争议已解决。未引入现代第三方解释全文，未导入多来源混写的现代解读。

## 获取、重建与发布

本轮通过维基文库官方 MediaWiki API，以合规 User-Agent 读取页面 wikitext 与修订 ID；源页未用展开后的“全览”代替子页快照。原文快照按修订固定，SHA-256 保存在 `sources.json`，来源页链接也固定 oldid。

`npm run knowledge:build` 从本地固定快照离线构建。`npm run knowledge:audit` 核验快照哈希、发布哈希、旧文字不退化、注解原文跨度可还原、64 卦基本位置齐全。

构建同一 release 时若证据内容 SHA-256 不同会拒绝；内容修改必须新建 release ID 并保留旧目录。`active.json` 只选择新会话默认版本；历史会话使用保存的 release。`npm run corpus:build` 继续只重建旧版基线，不自动覆盖新版。

原有 Open I Ching 上游的学习交流/非商业用途限制仍适用于其数据部分。新增资料不消除旧限制，项目不具有统一的可商用数据授权结论。具体原文、底本与版本描述分别见 `sources.json`、`works.json`、发布证据，不能把站点名当作可靠性保证。

检索用 OpenCC `TSCharacters.txt` 固定提交 `528ae2624972301649fbd00bbd837ce4e085650b`，附原始 LICENSE（Apache-2.0）。这里只做按字词面归一，不宣称完整 OpenCC 词组转换；原文展示和引用校验完全不做简繁替换。

## 检索与生成

`get_passages` 保留原精确检索并增加作者、著作、层次、版本、锚点过滤；`search_knowledge` 使用中文二字片段倒排召回与 BM25 排序，再加完整短语奖励。这是词面检索，不是向量语义检索。`Retriever.searchSemantic` 只保留可选接口，尚未启用。

默认读取原典；读取注解需要 `layers: ['commentary']` 或作者过滤，防止经文查询被注释替代。指定作者/著作是硬约束，不用别家材料填空。工具返回 `coverageStatus`、`missingTargets`、`noHitReason`、`truncated`；完整段落按记录数和字符预算选择，绝不截断引文。覆盖信息描述本地发布，不代表原作者从未写过。

首次 Workflow 仍不由模型规划计算。固定取证保留必要原典，并可按动爻与问题词面相关性自动补最多三位注家的各一段（附加注解总预算 1800 字符）。用户无需点名注家；无动爻时只有与问题存在词面命中的爻注才补入，避免任意选择一爻。追问模型可主动决定是否补检索，以辅助回应实际处境。古注是历史解释，不能当现实预测或必须执行的指令。
