## 数字如何解释

`summary.json` 和逐条记录可复算：

- 以最相近对读本为主比较：54 条经已声明的标点、繁简、字形处理后同文；8 条只剩常见字形差；3 条程注存在待判文字差。
- 把朱注另一版本也纳入：25 条所有比对同文；16 条仅字形差；24 条有版本或转录文字差，保持待核。
- 42 条朱注均与 KR1a0032 同文，但同一数字转录谱系不能排除，因此**不等于42条已证明没有错字**。与原本比出的21条实质文字差可能来自底本，也可能来自任一电子转录错误。
- 程注23条中22条与易学网电子文本在声明的规范化后同文，谦上六“大甚／太甚”有异。乾九三则揭示“两个网站同文”仍可能与其声称的扫描底本不同。

不要把“24条存在差异”报道为“24条知识错误”，也不要把“同文”写作人工审核通过。

## 值得优先复核的内容

1. **程颐乾九三：人／臣。** 当前“三雖人位”，KR1a0016“三雖臣位”。已查看 [卷一二b扫描](https://www.eee-learning.com/eeebook/yichen/yi-chen-juan013.gif)，右数第五栏开头清楚为“三雖臣位”。易学网电子版同样写“人”，与它所链接的扫描不一致。当前维基文库“通行本”的具体底本未明，因此记录为“与四库影像不一致，需明确版本”；不凭多数替换现有原文。原图与可阅 PNG 在 `raw/eee-cheng-scan-13.*`。
2. **程颐谦六四：己／已。** 当前“而己居其上”，KR1a0016“而已居其上”；易学网与当前一致。可能是对读本形近转录，未以它反改当前文本。
3. **程颐谦上六：大甚／太甚。** 当前“大甚”，另两电子对读“太甚”。大／太可存在古书通用和版本差，不能仅据现代用法判错。
4. **朱熹乾初九：常观／当观、画卦／卦画。** 当前和别本作“常觀”“畫卦”，原本作“當觀”“卦畫”。需要两个底本的对应影像判定，不能用原本强行修订别本。
5. **朱熹对读库自身有疑似转录字。** 原本出现谦六二“有閫”（当前“有聞”）、恒上六“振怕”（当前“振恒”）、乾九三“居卜之上”（当前“居下之上”）等。它们是对读材料的疑点，不能移植入当前语料。
6. **朱熹坎九五：象占／象。** 当前/别本“故其象占如此”，原本“故其象如此”。对齐已限定在该爻注，未将上六同尾句误拼进来。逐条比对保留这一字差。

## 方法与局限

离线复跑：在项目根执行 `python scripts/knowledge/review-song.py`。依赖 Python 标准库和已保存快照，不请求网络、不调用模型、不写发布数据。

比较严格限制在对应卦的片段内，定位正文后保存原始匹配窗口、卷页标记、行号、规范化字符串及每一处增删改。汉字匹配忽略标点、空白、页标、排版括号，采用固定的 OpenCC 单字表及显式字形映射；这些仅供比对，不改写 source text。`normalization.json` 披露基础规则；额外常见字形差仍保留在 `differences` 并分类，不直接消掉。

原本不含别本前置音读，因此含“○”的朱注比较原本时仅比较其后注释正文。不能据此声称音读已在原本获得印证。人物署名核对限于书名/作者标题；引文中的嵌套古人话语、音读作者的细分归属还需专门版本学审核。

易学网的 `lineStart/lineEnd` 是 HTMLParser 输出文本的逻辑行，而不是服务器 HTML 的行数。Kanripo 行号是快照真实文本行号。每条实际证据保留完整来源URL和文件哈希以便定位。
