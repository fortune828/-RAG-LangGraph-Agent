# 本轮固定输入与检索审查

创建时基线为 `b4c73d4`、graph v10 / prompt v16、`knowledge-v3-20260926-r1`。本目录没有调用模型 API，没有更改生产代码。

## 数据与隔离

- `development.json`：6 个固定输入轮次、5 个独立 group。前 3 题用于模型配置及 memory / classic / full 知识输入比较；后 3 题用于 B / C / D 检索策略比较。项目初问与纠正共享 group，不算两个独立会话。
- `holdout.json`：6 个新输入、6 个 group，生活 2、复杂取舍 1、同题纠正 1、信息缺口 1、风险 1。主优化者先冻结候选方案，再打开或运行；不得根据其输出继续调优后仍称未见留出。
- `*-freeze.json`：完整文件 SHA256、语料哈希及类别数量。冻结文件自身不包含问题正文。
- `development-retrieval-check.json`：离线执行既有 C/W1 规则和真实知识工具的结果；不是模型能力或回答质量分数。

只允许 `question`、`currentQuestion`、`mode`、`lineValues`、`history` 进入模型输入。`expectedEvidenceGroups`、`retrievalNecessity`、`reviewPoints`、`initialEvidenceAudit` 均为评测标签，禁止进入模型和规则策略。`history` 中 user / assistant 为角色分明的合成文本，助手历史含待纠正的猜测，不是用户事实。

所有标签由 AI 拟定并对照当前语料检查，**没有经过专家或用户人工标注**。证据组内是替代项，组间是分别检查的目标；日常题只为方便检查列出若干相关依据，不表示回答只能取这些卦意。空组列表不代表零质量，而是无指定文献目标。留出作者看过留出案例，因此这只是相对主优化过程隔离的小型开发留出，不是独立专家基准。

## 当前初始检索实际做了什么

[`backend/knowledge.py:144`](../../../../backend/knowledge.py) 固定读本卦卦辞、彖、大象；有动爻再读对应爻辞和小象，变卦不同再读其卦辞和大象。注释候选仅限本卦，存在动爻时限定在动爻；只选 20–1,200 字的单条注释，每位作者最多 1 条，总正文预算 1,800 字。按问题前 160 字的词面得分选择；无动爻且无命中则不选注释。

当前语料的 112 条注释仅覆盖 8 卦（1、2、3、4、15、16、29、32），各作者、各爻覆盖仍不齐。选择模型或增加检索次数不能自动补齐不存在的语料。正文级语义判断仍要对照材料，来源固定不等于已人工校勘。

[`backend/graph.py:208`](../../../../backend/graph.py) 在固定读取之外还复用前两轮最多 12 条同发布集、在权限范围内的证据；原典是必保留项，其他材料进入 16,000 个序列化字符 / 36 条的总体证据预算。当前 fixtures 历史没有证据，因此初始证据差异不会来自旧轮检索结果。

[`backend/graph.py:243`](../../../../backend/graph.py) 普通首问且没有显式对象缺口直接生成，不经过模型路由。所谓完整 Agent 不是所有题都发生自主检索决策；初问生活题的 D 与 B 很可能在工具路径上完全相同。

## 开发题的可验证差异

| 输入 | 初始证据状况 | C/W1 离线核验 | 比较用途 |
|---|---|---|---|

规则基线使用现有 [`evaluation/workflow.py:21`](../../../../evaluation/workflow.py)，不读取标签。确切缺口两次工具调用源于逐目标处理；模型可能合并 sections 一次取得两项，但是否节省整体成本仍取决于路由模型额外调用，不能只比较工具次数。模糊题 C 也能命中正确材料；没有把 Workflow 故意设计成无效检索。

## 对实验和优化的建议

1. memory 对照若沿用“文献解释只能依据本轮参考原文”，会变成禁止模型使用自身知识的对照。离线消融应明确只替换这一依据来源要求，保留同一生成协议、卦象与用户事实；不要求没有外部证据的回答伪造引用。引用机械指标在该组应标 N/A，传统含义仍用相同资料作盲评依据。
2. classic / full 应记录实际证据 ID 差集。没有差集的题只能比较随机性，不能称增强 RAG；本组项目两题确有三家注释增量，但样本很小且共享同一卦和同一 group。
3. 当前无需增加检索框架。先看三家九二注释是否减少“利见大人”等解释中的无据发挥，再判断自动增加更多注释是否值得。简单题仅有固定原典仍可能冗长，不能把这一现象归因为未检索足够材料。
4. `initial_evidence` 每位作者最多一条，多个动爻或作者定位明确时可能仍有缺口；这是工具补取的真实作用。候选只要有词面交集即可入选，因此“已选择某注释”不等于与当前生活问题相关。
5. B/C/D 的出处问题与生活对话分表。B 无法取得新文献是预期能力边界，不宜用三个知识题的整体完成率直接声称 Agent 的自然对话更好。真正需要判断的是新取得的材料是否在正文中被准确使用。

主优化者尚未收到 holdout 问题正文。后续若改 fixture，必须另存新版本及哈希，不覆盖冻结文件后继续沿用旧哈希或留出标签。
