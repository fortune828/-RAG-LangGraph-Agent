## 1. 已落地的修改

| 修改 | 原因与实际边界 | 验证 |
|---|---|---|
| 新产品体验从正常API随机起卦开始 | 旧80题有78题无动爻，独立40题和生活40题全部无动爻；这不是生产算法错误，是评测覆盖缺陷。新会话抽到什么就保留什么，不改爻、不重抽、不筛答案 | 保存每次硬币、计算结果、会话、请求及回答；验证追问cast不变 |
| 用户体验、机器核验、知识语义审查分开 | 用户不需要重新算卦、逐字比对引用或充当古文专家；机械匹配也不能证明解释正确 | 新体验表四维：理解、关联、交流、帮助；增加三个CTX标签；另存机器结果和知识待审表 |
| 失败轮的用户更正仍进入历史 | 原 `history()` 只取completed，导致失败回答所在轮的用户原话也被丢弃 | 路由、生成均保留最近六个completed/failed轮的用户输入；助手正文只取completed，当前running不重复进入历史 |
| 混合原典/注解请求保留两种目标 | “先看原文，再看朱熹解释”有时只留下作者注解目标，正确检索到的原典又被生成过滤掉 | 两个真实随机会话验证原典和指定作者材料都进入生成；正反例回归 |
| 全库出处发现只认实际工具命中 | 原本宽泛作者目标可能被本卦的无关初始材料提前认作已取得；availability与生成可见材料口径不一致 | 用同一 `source_evidence()` 选择实际检索命中；保留权限范围与目标过滤 |
| 有限显式卦爻事实核验 | 程序已知本卦、变卦、动爻、爻名，明确错误可进入既有一次修复 | 只识别有限独立肯定句；引用、条件和问题有排除测试。没有宣称正则能核验任意自然语言或古文含义 |

实现集中在 [graph.py](../backend/graph.py)、[validation.py](../backend/validation.py)。没有新增生产Agent、模型路由、记忆服务或润色调用；模型仍是 Flash low/8192 主调用、同模型非思考/8192 一次修复。Prompt、Schema、前端、起卦算法、知识库发布和持久化数据结构未改。

旧会话读取保持兼容；旧图版本的未完成checkpoint仍遵循既有版本隔离规则，不承诺跨版本续跑。新增核验只能挡住它所识别的断言，不能把其余句子认证为正确。

## 3. 上下文问题：已经证实与尚未证实的原因

### 已证实：失败回答会带走用户更正

v17随机搬家对话中，第二轮用户明确说“周三上午”“周末没空”“妈妈已经同意不点火了”。这轮先遇到输出截断，修复又出现claim不在正文，最终失败。第三轮实际路由和生成请求中，这三个第二轮事实全部缺失，因为历史只选成功轮。

v18只修复这一筛选条件：用户输入不依赖助手是否成功作答。失败助手候选、错误日志仍不作为对话内容传入。保存了[实际旧请求与新历史重建对照](reports/context-20261011/failed-history-diagnostic.json)，并用真实记录写了回归测试。这个证据证明信息传递恢复，**不证明模型一定正确使用它**。第三轮自身提到不用明火，因此不能将该回答所有问题都归因于历史缺失。

### 已证实：正常成功轮中，历史在场仍会重复

陶艺/办展两段随机对话的实际生成请求包含前轮用户与助手内容；陶艺时间更正也在输入中。模型仍会重讲旧卦意、重新提出已解决的约束。独立出题的婚礼题也出现：开头承认父母让新人定日期，末尾又要求确认父母“周日是否接受”。这不是又调用了算卦程序，而是没有把已知状态贯彻到回答决策。

### 有证据的干扰源，但没有单一归因

陶艺第二轮只是更正空闲时间，路由却又取了13条变卦材料，生成证据7条增加到20条；第三轮仍有19条。这说明固定状态、既有解释和更多原文可能共同吸引生成注意力。但把材料恢复为首轮实际证据后，重复并没有稳定减少，不能据此断言“证据多就是根因”。

独立评审的解释是：模型常先口头接受更正，却继续维护此前生成的解释和论证方向。这与输出现象吻合，仍属于机制假说。不能从几次黑盒回答推断模型内部注意力，也不能把责任全推给LLM或某一种消息格式。

## 4. 六种小实验：保留负面结果，不把猜想直接上线

先通过真实API为两个已见开发情境随机起卦，各连续三轮；抽取其中四个追问的**实际生成请求**。每个候选只生成一次，沿用该次实际卦象、问题与用户事实，没有重新造静卦。不同因素的改动单独记录；仅生成回放，不做修复，与端到端成功率分表。

| 候选 | 改了什么 | 机械通过 | 独立AI交流均分 / 有效n | CTX重复解释 / 可评分n |
|---|---|---:|---:|---:|
| 原始4个追问 | 实际原请求/回答 | 4/4 | 1.25 / 4 | 3/4 |
| roles | 同样历史改用原生user/assistant消息 | 4/4 | 0.75 / 4 | 3/4 |
| background | 卦象资料前置，原生历史随后，当前问题最后 | 4/4 | 1.00 / 4 | 2/4 |

| task | 仅替换任务开头，强调依据新事实推进讨论 | 3/4 | 1.00 / 3 | 3/3 |
| user-history-only | 仅诊断：保留用户历史，移除助手历史 | 3/4 | 1.00 / 3 | 2/3 |

未交付输出记NA，同时保留在机械失败分母。task一例引用数超限；user-history-only一例正文截断；disabled一例claim不在正文。完整错误码见[汇总JSON](reports/context-20261011/summary.json)。各组只有两个情境、四次追问，不能据小差异做显著性或模型强弱结论；部分重排组更快，也没有据此宣称交流改善。

因此**不采用这些上下文重排、删除助手历史、提示词替换或Thinking变更**。生产Prompt保持v16，没有增加“禁止重复”词表、固定句数或追问模板。

独立AI只获得局部“文化助手连续对话”的任务和匿名材料，未读项目源码、完整规划、解盲键或主实现者结论；使用 `gpt-6-astra / high`。它同时为后续六段题目出题，故是独立于实现的AI评审，不是双盲真人研究、第二个独立评分者或专家。各组[逐条分数与原句理由](reports/context-20261011/ai-quality.json)均可复查。

## 5. 真实随机运行与版本边界

六段独立对话涉及婚礼、取名、搬家、寺院参观、登门送礼、家庭纪念。实际动爻数量为0爻1个、1爻2个、2爻2个、3爻1个；**那一个静卦也照常保留**。最终v18午饭抽到谦→豫、2动爻；理发抽到大壮→师、3动爻。这是自然抽取结果，不是为凑覆盖指定。没有抽到的类别仍是缺口。

v17独立运行触发3次修复，2次完成；搬家第二轮失败。发现失败用户历史缺口后改为v18，再运行6轮开发冒烟，触发1次修复并完成。**18轮独立结果不能重新标成v18；最终v18尚无新的独立留出效果证明。** 两版问题和卦象不同，延迟差异也不能直接算成v18改进。

两条文献回归均实际取得并向生成传入所问原典和注解，“见金夫，不有躬”案例保留蒙六三原文、小象与朱熹材料。它证明目标和传递链路修复，不证明所有文义解释准确。保存了完整请求、工具结果、最终可见证据及回答，见[knowledge记录](reports/context-20261011/knowledge/rows.json)。

## 6. 回答的真实表现

独立AI对v17的17份可见回答给出的理解/关联/交流/帮助均分为 **1.71 / 0.88 / 0.88 / 1.65**；1份未交付为NA，仍计任务失败。另有两份虽返回insufficient且有说明，也不算完成用户目标。评审按实际要求判断，18轮中14轮完成任务，和机械完成17/18明显不同。

其标注CTX重复解释10轮、未利用用户修正1轮、重新解释已有状态2轮；标签可重叠，不能相加为错误回答总数。任务分数与逐条理由见[AI评阅](reports/context-20261011/human-random-v17/ai-review.md)。这些是AI主观参考，不是人类验收。

代表性正反证据：

- **理解有增量，但表达仍回绕**：婚礼回答能把“选哪天”切换到“周日怎么排不赶”，却再次要求确认父母是否同意周日。用户已明确父母让新人决定。
- **实际用到了更正**：送礼对话得知长辈不喝茶后改成水果，后续保持已购物品，不再要求补买。它仍重讲倒茶礼和旧卦义；不能把这两种现象都笼统标成“没记忆”。
- **任务脚本也有缺陷**：取名第二轮没给出候选，第三轮却预设存在“第一名”。模型指出没有候选是合理澄清，不能判为忘记历史；额外展开已经排除的旧名字才是重复。原脚本和输出全部保留。
- **最终版仍有明显失败体验**：午饭第三轮用户已选楼下面馆，只问怎样点单，回答仍遍历谦、九三、六四、豫，还把“雷出地奋”牵合成热气。理发第三轮交付了一句可用话术，却加入用户未确认的“保留能扎起来的长度”，随后再次展开大壮和师的解释。

最终v18六轮的独立AI理解/关联/交流/帮助均分为 **1.00 / 0.67 / 1.00 / 1.33**，CTX重复解释4/6、重新解释已有状态1/6、明确未利用用户修正0/6；后者不代表没有新增假设或历史污染。它们是不同问题、不同随机卦，不能与v17均分作升级效果比较。

所以本轮不宣称自然交流改善，尤其不能用最终6/6机械完成掩盖上述问题。完整上下文与回答均保留在阅读包，不只摘最好的一句。最终六轮的独立AI意见另见[最终版AI评阅](reports/context-20261011/human-random/ai-review.md)，应在用户自行评分之后阅读。

## 8. 尚未关闭的事项

1. **上下文中的决定没有稳定约束后续推理。** 有限筛选bug已修复，但重复解释和旧前提回流仍是首要体验问题，任务清单保留未完成。
2. **真引用依然会被硬套。** 本轮有限显式事实核验不能判断“雷出地奋=热气”或作者原义；知识语义表继续待审，不要求用户替机器查字，也不让机器冒充专家。
3. **独立出题仍有偏差。** 同一AI出题与评审，六段偏向家庭/礼俗，没有广泛用户代表性；脚本会预设上一轮已交付某对象。下一批应在保留原始计划的同时记录这类前提断裂，不能倒扣正确澄清。
4. **范围有意受限。** 没有新增正式40+40、未做长于六轮的真实对话验证，也没有为凑动爻类型重抽。现有成果足以展示“定位缺陷—控制变量—保留负面结果—小修复—回归验证”的工程过程，不足以承诺稳定优质解卦。

下一步优先依据用户新评分确认最影响体验的少数句子，继续区分事实传递与对话推进；不要因为本轮候选无效就增加记忆平台、更多Agent或禁止词模板。本轮到此停止修改。
